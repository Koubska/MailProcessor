# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Read first

- `AGENTS.md` holds the non-negotiable project rules. The most important ones: email data must stay on the local machine (no cloud, LLM or telemetry calls, and no LLM-based parsing). Never log full email bodies. Use only synthetic test data. Treat mail sources as read-only.
- `docs/requirements.md` is the specification and matches the current code. Its section 17 lists planned but unimplemented features, including an Outlook (COM) source, parser versioning, log files and GUI progress.

## Commands

Dependencies are locked in `uv.lock` (committed; CI installs with `--locked`). Groups: `dev` (pytest, ruff, installed by default), `build` (pyinstaller).

```bash
uv sync                                            # .venv with the app and the dev tools, from uv.lock

uv run pytest -q                                   # full suite (run from repo root; some tests read repo files by relative path)
uv run pytest tests/test_parser.py -q              # one file
uv run pytest tests/test_parser.py::test_name -q   # one test
uv run ruff check src tests scripts                # lint (rules in pyproject.toml, line length 120)
uvx --from actionlint-py actionlint                # check the workflow files

uv run mailprocessor --config ./config.toml --rules ./parsing_rules.toml [--dry-run] [--max-age-days N]
uv run mailprocessor                               # no arguments: opens the GUI (config files from the cwd, or next to the frozen exe)

uv sync --group build && uv run python scripts/build_executable.py --target-platform {linux|macos|windows}
                                                   # PyInstaller one-file bundle -> dist/mailprocessor-<platform>.zip
uv lock --upgrade                                  # update all locked versions (Dependabot does this weekly as a PR)
```

The app icon lives in `src/mailprocessor/assets/` (`icon.png` for the Tk window, also package data and `--add-data`; `icon.ico`/`icon.icns` for the Windows/macOS executables). The build script refuses to cross-compile, so `--target-platform` must match the host. No type checker is configured.

## Git workflow

`main` only changes through pull requests (squash merge, CI must pass: `Test (ubuntu-latest)`, `Test (windows-latest)`, `Test (macos-latest)`, `Lint`). Never commit on `main` or push to it.

```bash
git fetch origin && git switch -c fix/short-topic origin/main   # one branch per topic
# ... change, then: uv run pytest -q && uv run ruff check src tests scripts
git commit ...
git push -u origin fix/short-topic && gh pr create             # push the branch and open the PR
```

Claude may push branches and open pull requests; the user reviews and merges them. Never merge, never push `main` or tags. After a merge: `git switch main && git pull --ff-only`, and delete the local branch.

## Architecture

The pipeline lives in `processor.run_pipeline`:

```text
source (sources/*.py) → NormalizedMail (models.py) → parser.parse_mail → ledger (SQLite) + excel_writer (openpyxl)
```

- **Config** (`config.py`): the shipped defaults live in `src/mailprocessor/defaults/` (package data, also bundled by PyInstaller via `--add-data`). `create_missing_files` copies them next to the app when the GUI starts and they are missing; it never overwrites. There are two TOML files, each validated with pydantic. `config.toml` holds the `[app]` paths and limits, `[source]` with `type = "eml" | "imap"`, and the optional `[filter]` (`config.MailFilter`: `subject`/`sender` lists, case-insensitive "contains"; the old `source.imap.sender_filter` is migrated into it on load). `parsing_rules.toml` holds `[[profiles]]` (each a `name` plus `[[profiles.fields]]`; a file with only top-level `[[fields]]` loads as one profile named `Standard`, `config.DEFAULT_PROFILE_NAME`). Profile names are unique ignoring case and must be valid Excel sheet names (`profile_name_problem`). Each field has `column`, `required` and a `type` (`label`, `next_line`, `between`, `email`, or `regex`, the default for old files) plus that type's inputs (`label` as string or list, `start`/`end`, or `pattern`). `rule_patterns.build_pattern` turns the simple types into regex; `FieldRule.regex` is what the parser runs. Column names must be unique within a profile and patterns must compile; `ParsingRules.columns` lists all profiles' columns once. `load_app_config` resolves relative paths against the config file's directory, not the working directory. The IMAP password is optional in the config; `main.py` fills it from `MAILPROCESSOR_IMAP_PASSWORD` or a `getpass` prompt.
- **Sources**: each source yields `NormalizedMail`, or a `MailReadError` for one message it couldn't read. Sources must never raise for a single bad message; raising is reserved for connection- or folder-level failures. The source is selected in `processor.iter_source_messages`. Both sources turn raw message bytes into `NormalizedMail` via `email_content.parse_message_bytes`. Body text comes from the first `text/plain` part, falling back to text extracted from `text/html` (`sources/email_content.py`), and is normalized with `parser.normalize_body`. The IMAP source is strictly read-only: it selects the mailbox with `readonly=True` and only runs `UID SEARCH` and `UID FETCH`. All server access goes through `ReadOnlyImapClient`, an allow-list wrapper offering only `login`, `examine`, `uid_search`, `uid_fetch` and `logout`. `examine` requires the server's `[READ-ONLY]` confirmation, and fetches use `BODY.PEEK[]` so the `\Seen` flag is never set. `tests/test_imap_readonly_integration.py` runs the real `imaplib` against a scripted server and asserts the mailbox is unchanged. `tests/test_sources_readonly_guard.py` statically forbids mutating calls in `sources/`. Its default factory verifies TLS certificates and requires STARTTLS on plain connections. It takes an injectable `client_factory` so tests can supply a fake client. A new source (for example Outlook) should follow the same contract and keep COM objects out of every other layer.
- **Parser** (`parser.py`): `parse_mail` runs every profile (`parse_profiles`) and `best_result` picks one: fewest required fields missing (complete profiles first), then most fields found, ties to the first profile; `ParseResult.profile` names it, and a failure names the closest profile. Per profile, it runs each rule's regex (`FieldRule.regex`) against the normalized body followed by the mail's header lines (`NormalizedMail.header_text`), so text labels win and headers such as `From:` are the fallback. `tests/test_default_rules.py` checks the shipped defaults against `docs/example.eml`. If the pattern has capture groups, group 1 is the value; otherwise the whole match is used. Whitespace is collapsed either way. A missing required field turns the message into an error result; this does not raise an exception. The real-world sample format is in `docs/example.eml` (a German school contact form) and matches the patterns in `parsing_rules.toml`.
- **Write ordering** (`processor.run_pipeline`): `ExcelOutput` holds the workbook in memory and `Ledger` holds one open SQLite transaction. At the end of the run the workbook is saved atomically (temp file plus `os.replace`), and only then is the ledger committed. Keep that order so a crash or a workbook locked by Excel never leaves the ledger ahead of the workbook. `run_pipeline` takes an optional `progress(current, total)` callback (sources report their total via `on_total`; filtered messages still count) and a `threading.Event` to cancel; a cancelled run breaks before the next message and still saves and commits. Mails that don't match `app_cfg.filter` are skipped before the ledger lookup (never recorded, counted in `RunSummary.filtered`, their stale error rows removed); the IMAP source additionally passes the filter to `SEARCH`, but that is only a pre-selection. `RunSummary.problems` lists failed messages (name, missing columns, and the parsed text for the GUI's problem list; at most `MAX_PROBLEM_DETAILS`, held in memory only, never logged). `processor.start_over` (GUI "Alles neu exportieren") renames the workbook to a timestamped backup, then clears the ledger. With `dry_run`, the ledger is opened read-only and nothing is saved.
- **Ledger** (`ledger.py`): the primary key is `(source_type, source_location, message_identity, content_hash)`. `message_identity` is the `Message-ID` header. If that header is missing, both sources fall back to `email_content.build_message_identity`, a hash of date, from, subject and body; changing that formula would re-export processed mails. `is_already_processed` matches on identity + content hash only, ignoring source type and location, so moved folders and renamed mailboxes are not exported again. `content_hash` is SHA-256 of the body (empty for a `MailReadError`). Only `status='processed'` causes a message to be skipped, so failed messages are retried on every run. `max_messages` counts only new messages, not skipped ones. The ledger does not track a parser version yet.
- **Profiles in Excel** (`processor.data_sheets`): `[app] profile_sheets = "shared"` (default) writes every row to `sheet_data`, with a leading `PROFILE_COLUMN` (`Profil`, reserved) only if there are several profiles; `"per_profile"` writes one sheet per profile, named like it. `ExcelOutput` takes a dict of data sheets and `append_data(..., sheet=)`. `RunSummary.per_profile` and `Problem.profile` carry the profile to the GUI.
- **Excel** (`excel_writer.py`): it appends to one workbook that persists across runs. Columns are addressed by header name through `_Sheet`, never by position: missing columns are appended after everything used (also after unlabelled notes), nothing is moved or removed, so user columns survive and fields can be added, removed or reordered. Only a sheet with data but no header row is rejected (`SheetHeaderError`). The data sheet (default `daten`) gets the rule columns, then `FIXED_DATA_COLUMNS`: `Eingegangen am` (the mail's `Date`, local time, empty if unusable), `Übertragen am` (the run's `ExcelOutput.now`) as real dates with `DATE_FORMAT`, and `E-Mail-Inhalt` (body text, truncated to 32,767 characters); these names are reserved in `ParsingRules`. The error sheet (default `fehler`) has German `ERROR_COLUMNS` (file name, sender, subject, dates, missing fields, plain-German `Grund`) plus the hidden `Kennung` (`error_key`), which `upsert_error`/`remove_errors_for` use to keep one row per failing mail; English error sheets of earlier versions (`LEGACY_ERROR_COLUMNS`) are converted on open. The workbook is German, like its sheet names. `_cell_value` strips control characters openpyxl rejects, and `_Sheet.append` forces strings starting with `=` to text, because email content is untrusted (formula injection).
- **Logging**: modules log to `mailprocessor.*` loggers. `logfile.attach_log_file` adds a rotating file handler (`logs/mailprocessor.log` next to the config; CLI and GUI attach it per run, replacing any previous one), so everything logged also lands on disk. `tests/conftest.py` detaches it after each test. Name mails with `item.display_name` (file name or IMAP uid plus Message-ID) so users can find them. Never log body text or extracted values; only column names and reasons. The CLI configures stderr logging from `log_level`; the GUI attaches `gui.QueueLogHandler` to the `mailprocessor` logger, sets its level from `log_level` on each run, and streams lines into the output box via the same queue as the run result.
- **CLI** (`main.py`): it catches `ValueError` and `OSError` and prints `Error: <msg>`. Other exceptions print a one-line message, and the traceback is logged at DEBUG level. Typer's pretty tracebacks are disabled. The `if __name__ == "__main__"` block is required because PyInstaller runs this file as a script, and `tests/test_main.py` guards it.
- **GUI** (`gui_app.py` window, `gui.py`/`ui_model.py`/`preview.py` testable logic, `i18n.py`): tabs Start (status cards, run), E-Mails (source, IMAP connection test), Felder (rules + live sample mail), Einstellungen. Inputs live in `App.form` (tk variables keyed like `ui_model.form_values`); the profiles live in `App.profiles`, a `ui_model.ProfileList` (one `RuleList` per profile; a profile without fields is kept while editing but not saved or run), and `App.fields` is the shown profile's `RuleList`. The column input suggests other profiles' columns (`ProfileList.column_suggestions`, inline `complete_column` for new fields; choosing one copies that profile's rule) and `ui_model.column_note` says whether the column is shared, own, or a near-duplicate spelling. The `RuleList` validates every change like the rules file and can undo the last removal (the footer shows "Rückgängig" instead of a delete confirmation). On Windows, `run_app` first calls `gui.enable_windows_dpi_awareness` (system DPI aware, so text is sharp at 125/150 %); Tk then scales fonts itself, and every size given in pixels (window size, wrap widths, table columns, row height) must go through `App.px`, which multiplies by `gui.ui_scale` (1.0 on macOS/Linux and at 100 %). `tests/test_display_scaling.py` includes a test that runs only on the Windows CI runner against the real API. Hover hints use `gui_app.Tooltip` (texts under `tip.*`), keyboard shortcuts come from `ui_model.shortcuts` (Command on macOS, Control elsewhere; ignored inside the sample mail text), and window size, position and tab are restored from `data/window.json` via `window_state.py` only if the window would be visible on the current screen. every change is debounced and saved by `App.save_config` only if `ui_model.config_from_form` reports no errors, which are shown in `App.error_labels`; rules are saved on every valid change. It runs `run_pipeline` on a worker thread and passes the result back to the UI through a queue polled with `root.after`. It never writes the IMAP password to disk. `main.main()` opens it when there are no CLI arguments; if Tk or a display is unavailable, it falls back to the CLI help. The "Felder" tab is split: rules on the left, a sample mail on the right (`preview.py`: `load_sample`, `preview_rule` computes values exactly like a run and a span for highlighting, `summary_text`); results update live (debounced `schedule_preview`). The rule editor shows only the chosen type's inputs; `rule_from_inputs` validates them with German/English messages and `describe_rule` produces the list's description. Only `gui_app.py` imports tkinter, and `gui.launch_gui` imports it lazily, so the CLI and the tests run without a display. Expected failures raise the typed exceptions in `errors.py` (subclasses of `ValueError`/`OSError`, so the CLI is unaffected); `gui.friendly_error` maps them to plain-language texts with the technical message as details, and `gui.run_summary_text` replaces the raw counters after a run. UI strings go through `i18n.t(key, lang)`. German is the default, English is the fallback, and every key must exist in both catalogs; `tests/test_i18n.py` scans the source for dotted string literals and fails on missing or unused keys (add file or host name endings to `NOT_KEYS`, runtime-built key prefixes to `DYNAMIC_PREFIXES`).

## CI

GitHub Actions (`.github/workflows/ci.yml`), all installs from `uv.lock`: `test` runs `pytest -q` on Ubuntu, Windows and macOS and `lint` runs ruff and actionlint, for every push and pull request. Only for tags, `build` (needs both) writes the tag into `version` in `pyproject.toml` (`uv version`, not committed; the value in the repository is not maintained), then builds the three ZIPs (macOS on `macos-latest`, i.e. Apple Silicon) and attests their provenance (`actions/attest-build-provenance`), and `release` (needs `build`) creates the GitHub release with `gh release create --generate-notes`, attaching the ZIPs. Release a version by tagging the merged commit on `main`: `git switch main && git pull --ff-only && git tag -a X.Y -m "X.Y" && git push origin X.Y` (tags are not affected by the branch rules). `.github/dependabot.yml` opens one grouped update PR per week for the Python packages (`uv.lock`) and for the actions. Dependabot PRs also run `build` (no tag version, no attestation); the `dependabot-merge` job (needs test, lint and build) squash-merges them when `dependabot/fetch-metadata` reports a patch or minor update. Major updates are left for review. Merges made with the workflow token do not start a new CI run on `main`. `tests/test_github_workflow.py` and `tests/test_build_executable.py` assert parts of this structure (tag gating, job order, tag version, locked installs, executable names, generated `RUNNING.md`), so update them when you change the workflow or the build script.
