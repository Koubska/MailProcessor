# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Read first

- `AGENTS.md` holds the non-negotiable project rules. The most important ones: email data must stay on the local machine (no cloud, LLM or telemetry calls, and no LLM-based parsing). Never log full email bodies. Use only synthetic test data. Treat mail sources as read-only.
- `docs/requirements.md` is the specification and matches the current code. Its section 17 lists planned but unimplemented features, including an Outlook (COM) source, parser versioning, log files and GUI progress.

## Commands

```bash
python -m venv .venv && . .venv/bin/activate
pip install -e . pytest          # pytest is not a declared dependency

pytest -q                                          # full suite (run from repo root; some tests read repo files by relative path)
pytest tests/test_parser.py -q                     # one file
pytest tests/test_parser.py::test_name -q          # one test

mailprocessor --config ./config.toml --rules ./parsing_rules.toml [--dry-run] [--max-age-days N]
mailprocessor                                      # no arguments: opens the GUI (config files from the cwd, or next to the frozen exe)

python scripts/build_executable.py --target-platform {linux|macos|windows}   # PyInstaller one-file bundle -> dist/mailprocessor-<platform>.zip
```

The app icon lives in `src/mailprocessor/assets/` (`icon.png` for the Tk window, also package data and `--add-data`; `icon.ico`/`icon.icns` for the Windows/macOS executables). The build script refuses to cross-compile, so `--target-platform` must match the host. No linter or type checker is configured.

## Architecture

The pipeline lives in `processor.run_pipeline`:

```text
source (sources/*.py) → NormalizedMail (models.py) → parser.parse_mail → ledger (SQLite) + excel_writer (openpyxl)
```

- **Config** (`config.py`): the shipped defaults live in `src/mailprocessor/defaults/` (package data, also bundled by PyInstaller via `--add-data`). `create_missing_files` copies them next to the app when the GUI starts and they are missing; it never overwrites. There are two TOML files, each validated with pydantic. `config.toml` holds the `[app]` paths and limits plus `[source]` with `type = "eml" | "imap"`. `parsing_rules.toml` holds a list of `[[fields]]` entries, each with `column`, `required` and a `type` (`label`, `next_line`, `between`, `email`, or `regex`, the default for old files) plus that type's inputs (`label` as string or list, `start`/`end`, or `pattern`). `rule_patterns.build_pattern` turns the simple types into regex; `FieldRule.regex` is what the parser runs. Column names must be unique and patterns must compile. `load_app_config` resolves relative paths against the config file's directory, not the working directory. The IMAP password is optional in the config; `main.py` fills it from `MAILPROCESSOR_IMAP_PASSWORD` or a `getpass` prompt.
- **Sources**: each source yields `NormalizedMail`, or a `MailReadError` for one message it couldn't read. Sources must never raise for a single bad message; raising is reserved for connection- or folder-level failures. The source is selected in `processor.iter_source_messages`. Both sources turn raw message bytes into `NormalizedMail` via `email_content.parse_message_bytes`. Body text comes from the first `text/plain` part, falling back to text extracted from `text/html` (`sources/email_content.py`), and is normalized with `parser.normalize_body`. The IMAP source is strictly read-only: it selects the mailbox with `readonly=True` and only runs `UID SEARCH` and `UID FETCH`. All server access goes through `ReadOnlyImapClient`, an allow-list wrapper offering only `login`, `examine`, `uid_search`, `uid_fetch` and `logout`. `examine` requires the server's `[READ-ONLY]` confirmation, and fetches use `BODY.PEEK[]` so the `\Seen` flag is never set. `tests/test_imap_readonly_integration.py` runs the real `imaplib` against a scripted server and asserts the mailbox is unchanged. `tests/test_sources_readonly_guard.py` statically forbids mutating calls in `sources/`. Its default factory verifies TLS certificates and requires STARTTLS on plain connections. It takes an injectable `client_factory` so tests can supply a fake client. A new source (for example Outlook) should follow the same contract and keep COM objects out of every other layer.
- **Parser** (`parser.py`): it runs each rule's regex (`FieldRule.regex`) against the normalized body followed by the mail's header lines (`NormalizedMail.header_text`), so text labels win and headers such as `From:` are the fallback. `tests/test_default_rules.py` checks the shipped defaults against `docs/example.eml`. If the pattern has capture groups, group 1 is the value; otherwise the whole match is used. Whitespace is collapsed either way. A missing required field turns the message into an error result; this does not raise an exception. The real-world sample format is in `docs/example.eml` (a German school contact form) and matches the patterns in `parsing_rules.toml`.
- **Write ordering** (`processor.run_pipeline`): `ExcelOutput` holds the workbook in memory and `Ledger` holds one open SQLite transaction. At the end of the run the workbook is saved atomically (temp file plus `os.replace`), and only then is the ledger committed. Keep that order so a crash or a workbook locked by Excel never leaves the ledger ahead of the workbook. `run_pipeline` takes an optional `progress(current, total)` callback (sources report their total via `on_total`; filtered messages still count) and a `threading.Event` to cancel; a cancelled run breaks before the next message and still saves and commits. `processor.start_over` (GUI "Alles neu exportieren") renames the workbook to a timestamped backup, then clears the ledger. With `dry_run`, the ledger is opened read-only and nothing is saved.
- **Ledger** (`ledger.py`): the primary key is `(source_type, source_location, message_identity, content_hash)`. `message_identity` is the `Message-ID` header. If that header is missing, both sources fall back to `email_content.build_message_identity`, a hash of date, from, subject and body; changing that formula would re-export processed mails. `is_already_processed` matches on identity + content hash only, ignoring source type and location, so moved folders and renamed mailboxes are not exported again. `content_hash` is SHA-256 of the body (empty for a `MailReadError`). Only `status='processed'` causes a message to be skipped, so failed messages are retried on every run. `max_messages` counts only new messages, not skipped ones. The ledger does not track a parser version yet.
- **Excel** (`excel_writer.py`): it appends to one workbook that persists across runs. Successfully parsed rows go to the data sheet (default `daten`), whose last column is always `CONTENT_COLUMN` (`E-Mail-Inhalt`, the mail's body text, truncated to Excel's 32,767-character cell limit); the name is reserved in `ParsingRules`, and older workbooks without it get the header added on open. `_cell_text` strips control characters openpyxl rejects from every value. Failures go to the error sheet (default `fehler`), which has fixed `ERROR_COLUMNS` and keeps one row per failing message (`upsert_error`); the row is removed once the message succeeds. An existing sheet whose header differs from the rule columns is rejected rather than appended to. Every write goes through `_append_text_row`, which forces strings starting with `=` to text, because email content is untrusted (formula injection).
- **Logging**: modules log to `mailprocessor.*` loggers. `logfile.attach_log_file` adds a rotating file handler (`logs/mailprocessor.log` next to the config; CLI and GUI attach it per run, replacing any previous one), so everything logged also lands on disk. `tests/conftest.py` detaches it after each test. Name mails with `item.display_name` (file name or IMAP uid plus Message-ID) so users can find them. Never log body text or extracted values; only column names and reasons. The CLI configures stderr logging from `log_level`; the GUI attaches `gui.QueueLogHandler` to the `mailprocessor` logger, sets its level from `log_level` on each run, and streams lines into the output box via the same queue as the run result.
- **CLI** (`main.py`): it catches `ValueError` and `OSError` and prints `Error: <msg>`. Other exceptions print a one-line message, and the traceback is logged at DEBUG level. Typer's pretty tracebacks are disabled. The `if __name__ == "__main__"` block is required because PyInstaller runs this file as a script, and `tests/test_main.py` guards it.
- **GUI** (`gui.py`, `i18n.py`): a tkinter editor for `config.toml` and `parsing_rules.toml`. It runs `run_pipeline` on a worker thread and passes the result back to the UI through a queue polled with `root.after`. It never writes the IMAP password to disk. `main.main()` opens it when there are no CLI arguments; if Tk or a display is unavailable, it falls back to the CLI help. The "Parsing-Felder" tab is split: rules on the left, a sample mail on the right (`preview.py`: `load_sample`, `preview_rule` computes values exactly like a run and a span for highlighting, `summary_text`); results update live (debounced `schedule_preview`). The rule editor shows only the chosen type's inputs; `rule_from_inputs` validates them with German/English messages and `describe_rule` produces the list's description. The pure functions `parse_*_text` and `render_*_text` are separate from `launch_gui`, which imports tkinter lazily, so the tests can run without a display. Expected failures raise the typed exceptions in `errors.py` (subclasses of `ValueError`/`OSError`, so the CLI is unaffected); `gui.friendly_error` maps them to plain-language texts with the technical message as details, and `gui.run_summary_text` replaces the raw counters after a run. UI strings go through `i18n.t(key, lang)`. German is the default, English is the fallback, and every key must exist in both catalogs.

## CI

GitHub Actions (`.github/workflows/ci.yml`): `test` runs `pytest -q` on Ubuntu, Windows and macOS for every push and pull request. Only for tags, `build` (needs `test`) builds the three ZIPs (macOS on `macos-latest`, i.e. Apple Silicon), and `release` (needs `build`) creates the GitHub release with `gh release create`, attaching the ZIPs. Release a version by bumping `version` in `pyproject.toml`, then `git tag -a X.Y -m "X.Y" && git push origin X.Y`. `tests/test_github_workflow.py` and `tests/test_build_executable.py` assert parts of this structure (tag gating, job order, executable names, generated `RUNNING.md`), so update them when you change the workflow or the build script. Check workflow edits with `uvx --from actionlint-py actionlint .github/workflows/ci.yml`.
